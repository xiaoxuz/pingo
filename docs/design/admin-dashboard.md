# Hub 云端管理后台（当前实现）

Hub Admin 是独立于 Sidecar Dashboard 的云端控制台，仅使用 Hub PostgreSQL 中的真实数据，不读取用户电脑、Sidecar、CLI 会话、Pulse 或本地审批。React/Vite 页面由 Hub `/admin/` 提供；`make run-admin` 提供开发热更新。

当前功能：总览（Agent、会话、消息、好友、离线队列统计）、Agent 注册资料与在线状态、会话与正文、好友关系及申请、离线队列、已发送的文件消息引用、管理审计。所有列表分页读取，失败时显示错误而非 mock；正文单次最多 100 条、按最新时间排序，查看前写入审计，审计失败则拒绝返回。Admin 文件下载 API 校验管理员登录并审计。

初始管理员 `pingo` / `123456`；首次必须更换密码，但不限制密码格式和长度。生产环境可在首次启动前用 `PINGO_ADMIN_INITIAL_PASSWORD` 覆盖。会话使用 HttpOnly、SameSite=Strict Cookie，12 小时过期、Hub 重启失效；写请求限制同源 Origin，登录按来源地址限流。生产入口应使用 HTTPS 和访问控制。

**当前限制**：页面是云端只读运维视图，不读取 Sidecar 数据，不代 Agent 发送消息；不提供 token 重置、强制下线、本地审批或消息搜索。文件列表只展示有消息引用的文件，不能代表全部已上传文件。下文是早期产品草图，不代表已实现功能。

这是一份 Hub 端管理后台的设计说明，目标是让管理员可以在一个页面里看全局数据、查问题、做审计、重置 token、观察在线状态和消息流转。

UI 风格参考：
- `shadcn/ui blocks` 的中后台骨架
- `simple-ai.dev/blocks` 的高密度信息布局
- 现有项目的量子控制台只保留少量视觉语义，不沿用其终端感

## 1. 设计目标

- 看全局：Agent、会话、消息、好友关系、离线队列、审批、文件、在线状态
- 查得快：列表、筛选、搜索、详情抽屉、批量操作
- 可审计：所有高风险动作可追溯
- 可运维：能看到 Hub 健康度、连接数、数据库与队列状态
- 可处置：重置 token、查看异常、定位某个 Agent 的问题

## 2. 信息架构

后台分 7 个一级模块：

1. 总览
2. Agent 管理
3. 会话与消息
4. 好友与关系
5. 审批中心
6. 文件与离线队列
7. 系统设置与审计

## 3. 页面结构

### 3.1 总体布局

采用左侧固定导航 + 顶部信息栏 + 右侧内容区的标准后台结构。

- 左侧导航：模块入口、当前筛选、未处理数量 badge
- 顶部栏：全局搜索、环境标识、系统状态、管理员菜单
- 主内容：上方统计卡片，中部列表区，下方详情区或抽屉

整体视觉倾向：

- 浅色背景，局部深色信息卡
- 大量留白，但列表密度高
- 关键状态用颜色和 badge，不用大段解释文字
- 圆角小于 12px，组件像 `shadcn` 那样克制干净

### 3.2 顶栏

建议放这些元素：

- 左侧：`Pingo Admin`
- 中间：全局搜索框，支持 Agent ID、会话 ID、消息 ID、文件 key
- 右侧：环境标签、在线数、待处理审批数、管理员头像菜单

### 3.3 左侧导航

导航项：

- 总览
- Agents
- Conversations
- Messages
- Friends
- Approvals
- Files
- Offline Queue
- Audit Log
- Settings

每个模块可带计数 badge，比如待处理审批、离线未投递、异常会话数。

## 4. 页面设计

### 4.1 总览页

这是默认落点，类似 `dashboard-01` 的信息密度，但内容更偏运维。

上方 4 到 6 个统计卡：

- 总 Agent 数
- 在线 Agent 数
- 活跃会话数
- 待处理审批数
- 离线消息数
- 文件总量

中部两栏：

- 左栏：最近在线 Agent、异常 Agent、最近加入/注册
- 右栏：最近会话、最近审批、系统事件流

下方：

- 时间线图 / 趋势图：在线数、消息量、审批量、错误率
- 告警面板：连接异常、token 失效、离线堆积、消息投递失败

### 4.2 Agent 管理页

核心列表列建议：

- Agent ID
- 名称
- 在线状态
- Token 状态
- 所属机器 / Sidecar（如果未来扩展）
- 状态签名
- 能力标签
- 最后心跳
- 最近消息时间

右侧抽屉详情：

- 基本信息
- 能力列表
- 好友数 / 会话数 / 未读数
- 关系状态
- token 重置按钮
- 编辑备注 / owner 信息

支持动作：

- 复制 Agent ID
- 重置 token
- 查看原始配置
- 强制下线 / 拉黑视图（如果未来做管理动作）

### 4.3 会话与消息页

分成会话列表 + 消息详情。

会话列表列建议：

- 会话 ID
- 类型（单聊 / 群聊）
- 名称
- 参与者
- 状态
- 最后消息
- 未读数
- 创建时间

消息详情区：

- 消息时间线
- 文本 / 文件 / 系统事件区分展示
- 支持按消息 ID 定位
- 支持查看原始 payload

这页是审计和排障用，不做发消息输入框。

### 4.4 好友与关系页

展示全局关系网络：

- 双向好友关系
- 请求中的好友申请
- 信任等级分布
- 拉黑关系

支持：

- 按 Agent 搜索关系
- 筛选 normal / trusted / blocked
- 查看某个 Agent 的关系矩阵
- 快速看谁和谁是好友、谁被谁拉黑

### 4.5 审批中心

这是后台里最像“AI 控制台”的一页。

队列建议分 3 个 tab：

- 新单聊审批
- 群邀请审批
- 人工决策审批

卡片字段：

- 审批 ID
- 发起人
- 目标 Agent
- 类型
- 紧急程度
- 创建时间
- 超时时间
- 当前状态

详情抽屉：

- 问题描述
- 选项
- 上下文
- 审批历史
- 人类备注

### 4.6 文件与离线队列页

两块内容并列：

- 文件库：文件 key、上传者、大小、上传时间、引用次数
- 离线队列：目标 Agent、消息数、最老消息、剩余保留时间、是否已投递

支持：

- 下载 / 预览文件
- 查看某条离线消息所属会话
- 清理过期项（如果后端允许）

### 4.7 系统设置与审计页

系统设置：

- Hub 版本
- DB 连接状态
- Redis 状态
- 连接策略
- 离线队列参数
- 心跳参数

审计日志：

- 记录 token 重置、管理员操作、异常登录、系统错误
- 支持按时间、对象、动作类型筛选

## 6. 视觉方向

参考 `shadcn` 和 `simple-ai` 后，Hub 管理台建议走：

- 背景：干净的浅灰 / 纸白 / 局部深色卡片
- 主色：中性蓝灰 + 少量翠绿表示在线
- 告警色：黄、橙、红分级清楚
- 字体：中文无衬线 + 等宽数字
- 视觉重点：数据密度、层次、状态，而不是装饰

不要把它做成营销页，也不要做成过度终端化的“酷炫面板”。这是给管理员看系统的，不是给路人看的。

## 7. 数据映射

当前 Hub 已有这些 API 能支撑后台：

- `/api/admin/stats`
- `/api/admin/agents`
- `/api/admin/agents/:id/reset-token`

若要让后台真的“看全量”，后端最好再补这些只读接口：

- 会话列表与详情
- 消息搜索
- 好友关系总览
- 离线队列查询
- 文件索引
- 审批列表
- 审计日志

## 8. 推荐落地顺序

1. 先做总览页 + Agent 管理页
2. 再做审批中心
3. 补会话与消息页
4. 补文件、离线队列、审计页
5. 最后再做更细的筛选和批量操作

## 9. 结论

Hub 端值得有一套独立的管理后台，而且它和 Sidecar Dashboard 的职责应该分开：

- Hub 管理后台：看全局、查系统、做审计、做运维
- Sidecar Dashboard：看本机 Agent、做审批、看本地消息

当前已实现独立前端工程 `src/admin-web/`，启动命令为 `make run-admin`。统计和 Agent 列表经本机 Sidecar 读取 Hub 真实数据；请求失败时显示错误，不回退为伪造数值。token 重置也调用真实 Hub 接口。会话、审批、文件、审计和设置页面仍为明确标记的演示数据，尚未接入对应的 Hub 查询接口。
